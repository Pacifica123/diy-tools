# DIY Tool Standard v0.2-devctl

Статус: прикладной стандарт разработки маленьких личных и полуличных инструментов. Версия 0.2 закрепляет, что именно означает зрелость M3 на общей полке и как это проверяется.

Этот каталог добавлен devctl-патчем. Он предназначен не как «ещё одна документация», а как стартовая методология для будущего зоопарка инструментов: скриптов, CLI, GUI, Electron/desktop-утилит, Rust/Go-бинарников, APK-оболочек и будущего менеджера инструментов.

## Что читать

1. `STANDARD.md` — канонический стандарт. Что должно лежать в капсуле уровня M3 — §4.1; история версий — §23.
2. `DEVCTL_PATCH_PROTOCOL.md` — как оформлять будущие изменения и новые инструменты через `devctl`.
3. `SOURCE_TOOL_AUDIT.md` — какие требования добавлены после разбора уже существующих инструментов.
4. `_templates/` — шаблоны README, `tool.ini`, контракта, истории изменений, лаунчеров, реестра, prompt-а и patch summary.
5. `standard_manifest.json` — машинно-читаемая карточка версии стандарта.

## Короткая формула

```text
Микропроблема → капсула инструмента → явный контракт → честный риск → минимальная проверка → devctl-патч → след в реестре.
```

Главная защита стандарта: он не должен становиться тяжелее самой микропроблемы. Уровни зрелости и флаги риска существуют именно для того, чтобы одноразовый скрипт не оформлялся как платформа, а опасный инструмент не маскировался под безобидную кнопку.

## Как проверить полку

```bash
python scripts/check_tools_shelf.py            # паспорта, реестр, требования M3 и smoke-тесты всех капсул
python scripts/check_tools_shelf.py --static   # то же без запуска smoke-тестов
```

Проверка сверяет `TOOLS.md` с `tool.ini` каждой капсулы, требует для M3 файлы из §4.1 стандарта, запускает smoke-тесты и убеждается, что они не оставили следов в капсулах. Если часть smoke-теста была пропущена из-за отсутствующей программы (`cargo`, `node`, `ffmpeg`, `git`), это печатается в итоге.
