# ABI mpl-json 0.1 (версия контракта: 1)

Это полное описание внешнего контракта `mpl`: на него может опираться другая программа или будущий автор. Короткий указатель — `docs/CONTRACT.md`.

ABI нужен, чтобы `mpl` можно было вызывать не только из GUI, но и из другого инструмента через JSON.

## Версии

| Что | Значение | Где видно |
|---|---|---|
| Версия контракта полки | `1` | поле `"contract_version": 1` во всём JSON, который выдаёт инструмент; `tool.ini [data] contract_version` |
| Имя и версия ABI | `mpl-json 0.1` | поле `"abi": {"name": "mpl-json", "version": "0.1"}` в JSON-результате |

`contract_version` — общий для полки целочисленный номер. `abi.version` — историческая метка самого `mpl`, она сохранена для совместимости. Несовместимое изменение = новая версия контракта (`contract_version` 2 и новая `abi.version`) + запись в `CHANGELOG.md`. Добавление новых необязательных полей и новых поддержанных конструкций Mermaid несовместимым изменением не считается.

## Вызов

```text
python main.py --cli [аргументы]        # из папки капсулы или по полному пути к main.py
./run.sh --cli [аргументы]              # Linux; run.bat --cli [аргументы] — Windows
```

Launcher и `main.py` не меняют текущую папку: относительные пути в аргументах считаются от папки, из которой запущена команда. Пути с пробелами и кириллицей поддерживаются.

| Аргумент | Смысл |
|---|---|
| `--input PATH`, `-i PATH` | входной файл Mermaid-subset, UTF-8 |
| `--text TEXT` | Mermaid-текст прямо в аргументе |
| `--stdin` | читать Mermaid-текст из stdin |
| `--abi-json` | читать ABI JSON из stdin, вернуть ABI JSON в stdout (остальные аргументы игнорируются) |
| `--svg PATH` | записать SVG в файл |
| `--ast PATH` | записать AST JSON в файл |
| `--json` | вывести полный JSON-результат в stdout |
| `--no-svg` | не строить SVG (`--svg` при этом ничего не пишет) |
| `--strict` | остановиться с ошибкой на первой неразобранной строке или лишнем `end` |
| `--fail-on-warning` | вернуть код 3, если есть предупреждения (файлы всё равно пишутся) |

Нужен ровно один источник: `--input`, `--text` или `--stdin` (либо режим `--abi-json`). Если не указаны ни `--svg`, ни `--ast`, JSON-результат выводится в stdout и без `--json`.

`python main.py` без `--cli` запускает GUI; GUI в контракт не входит.

## Вход

Формат диаграммы — UTF-8 Mermaid-subset, перечисленный в `README.md`, раздел «Вход». BOM в начале допускается. Неподдержанные строки не роняют обработку, а превращаются в предупреждения (кроме режима `--strict`).

Минимальный stdin JSON для `--abi-json`:

```json
{
  "source": "flowchart TD\nA[Старт] --> B[Финиш]",
  "render": true
}
```

Вместо `source` можно передать:

```json
{
  "input_path": "examples/input/basic_flow.mmd",
  "render": true
}
```

Поля входного JSON:

| Поле | Тип | Смысл |
|---|---|---|
| `source` (синоним `text`) | строка | текст диаграммы |
| `input_path` | строка | путь к файлу UTF-8; относительный путь считается от текущей папки процесса |
| `render` (синоним `svg`) | bool, по умолчанию `true` | строить ли SVG |
| `strict` | bool, по умолчанию `false` | то же, что `--strict` |

## Выход

JSON-результат (`--json`, `--abi-json` и вывод по умолчанию):

```json
{
  "ok": true,
  "diagram": {
    "kind": "flowchart",
    "direction": "TD",
    "nodes": [],
    "edges": [],
    "groups": [],
    "warnings": []
  },
  "warnings": [],
  "svg": "<svg ...",
  "abi": {
    "name": "mpl-json",
    "version": "0.1"
  },
  "contract_version": 1
}
```

Если `render=false` (или `--no-svg`), поле `svg` не возвращается.

Структура `diagram` (AST):

| Поле | Содержимое |
|---|---|
| `kind` | `flowchart` или `graph` — как в заголовке |
| `direction` | `TD`, `LR`, `RL`, `BT` (`TB` приводится к `TD`) |
| `nodes[]` | `id`, `label`, `shape` (`rect`, `round`, `circle`, `diamond`, `subroutine`, `cylinder`, `hex`, `parallelogram`, `parallelogram_alt`), `group` (id группы или `null`); порядок — порядок первого упоминания |
| `edges[]` | `source`, `target` (id узла или группы), `label`, `directed`, `bidirectional`, `style` (`normal`, `dotted`, `thick`); порядок — порядок в тексте |
| `groups[]` | `id`, `label`, `parent` (id внешней группы или `null`) |
| `warnings[]` | русские строки-предупреждения; те же строки дублируются в `warnings` верхнего уровня |

Файлы, которые пишет CLI:

- `--ast PATH` — AST JSON (UTF-8, отступ 2 пробела): объект `diagram`, перед полями которого добавлено `"contract_version": 1`. Это audit output: по нему видно, что именно понял парсер и какие были предупреждения.
- `--svg PATH` — SVG-документ UTF-8. Если были предупреждения, внизу картинки есть строка `warnings: N`.

Имена файлов задаёт вызывающий; существующий файл по указанному пути перезаписывается. Других файлов инструмент не создаёт.

### Ошибка в режиме `--abi-json`

При ошибке в stdout выдаётся JSON (и то же сообщение — в stderr), код возврата — из таблицы ниже:

```json
{
  "ok": false,
  "error": {
    "code": 2,
    "kind": "bad_input",
    "message": "строка 2: лишний end без subgraph"
  },
  "abi": {
    "name": "mpl-json",
    "version": "0.1"
  },
  "contract_version": 1
}
```

`error.kind` — `bad_input` (код 2) или `processing_error` (код 3). В остальных режимах при ошибке stdout пуст, сообщение идёт в stderr.

## stdout и stderr

- stdin и stdout CLI всегда в UTF-8, независимо от локали и ОС.
- Если JSON выводится в stdout, там нет ничего, кроме JSON.
- Если указаны `--svg`/`--ast`, CLI печатает итог: `Готово.`, счётчики, предупреждения, строки `Результат: <svg>` и `Отчёт: <ast>`. Итог идёт в stdout, а при одновременном `--json` — в stderr.
- Ошибки — одна русская строка в stderr вида `mpl: ошибка входа: ...` или `mpl: ошибка обработки: ...`, без traceback.

## Exit codes CLI

| Код | Значение |
|---:|---|
| 0 | Успешная обработка |
| 2 | Ошибка входа, JSON или файла; ошибка разбора в режиме `--strict`; неверные аргументы |
| 3 | Ошибка обработки; предупреждения при `--fail-on-warning` |
| 5 | Нет GUI-зависимости PySide6/PyQt6 при запуске GUI |

## Граница контракта

`mpl-json 0.1` стабилизирует структуру `nodes`, `edges`, `groups`, `warnings`, но не обещает пиксельную неизменность SVG-раскладки.

В контракт НЕ входят:

- координаты, размеры, цвета и CSS внутри SVG (регрессионные эталоны в `examples/output_expected` фиксируют текущую раскладку для проверки, а не обещают её навсегда);
- точный текст предупреждений, сообщений об ошибках и итогового отчёта;
- GUI и внутренние модули `mpl.core.*`; из Python поддерживаются `mpl.api.process_text()` / `process_file()` (возвращают тот же результат без полей `abi` и `contract_version`) и `mpl.abi.run_contract()`;
- совпадение с настоящим Mermaid за пределами описанного subset.
