# Внешний контракт Random Wheel App

Версия контракта: 1

Здесь описано то, на что может опираться другая программа или будущий автор: запуск, формат входа, файл сохранения/autosave, файлы экспорта и правило выбора при заданном seed.

Правило: несовместимое изменение любого пункта = новая версия контракта + запись в `CHANGELOG.md`. Совместимое дополнение (новое необязательное поле) версию не меняет.

## Запуск

| Что | Значение |
|---|---|
| Команда | `python main.py` (или `run.bat` / `sh run.sh`) |
| Аргументы | нет; аргументы командной строки передаются в Qt как есть |
| Код возврата `0` | окно закрыто штатно |
| Код возврата `1` | не найдена библиотека PySide6; в stderr — русское сообщение с командой установки |
| Код возврата `127` (`run.sh`) | не найден `python3` |
| stdout / stderr | при обычной работе пусто; итоги и ошибки показываются в окне |

CLI у инструмента нет. `python scripts/smoke_test.py` — проверка, а не рабочий режим.

## Вход

TXT-список вариантов. Формат и разбор «плохих» строк: [input_format.md](input_format.md).

## Файл сохранения / autosave

Один файл на пользователя: `~/.random_wheel_app_autosave.json` (домашний каталог: `Path.home()`; в Windows это `C:\Users\<имя>\`). Внутри капсулы инструмент ничего не сохраняет.

- Записывается при открытии колеса, после каждого вращения, после «Вернуть все варианты», «Очистить историю» и по кнопке «Сохранить».
- Слот один: открытие нового колеса перезаписывает прежний autosave. Если прежняя сессия нужна — скопируйте файл заранее.
- Запись идёт через соседний временный файл `.random_wheel_app_autosave.json.tmp` с последующей заменой, поэтому оборванная запись не портит прежнее сохранение.
- Кодировка UTF-8, JSON с отступом 2, кириллица не экранируется.

Пример: `examples/input/session_v1.json`.

| Поле | Тип | Смысл |
|---|---|---|
| `contract_version` | целое | версия этого формата; сейчас `1` |
| `items` | список объектов | все варианты колеса в порядке входного файла; не пустой |
| `items[].id` | целое | номер варианта, уникален в файле (с 1) |
| `items[].label` | строка | название, не пустое |
| `items[].value` | число или `null` | вес из входного файла; `null` — веса нет |
| `items[].source_line` | целое | номер строки во входном файле |
| `active_ids` | список целых | `id` вариантов, которые сейчас на колесе (в режиме «удалять выпавший вариант» список уменьшается) |
| `options.mode` | `"equal"` / `"weighted"` | режим: равные сегменты или по весу |
| `options.spin_duration_ms` | целое | длительность анимации, мс |
| `options.min_turns`, `options.max_turns` | целое | число оборотов анимации |
| `options.remove_winner` | `true` / `false` | удалять ли выпавший вариант с колеса |
| `options.random_seed` | целое | seed; `0` — случайный, результат невоспроизводим |
| `history` | список объектов | записи вращений, от старых к новым |
| `history[].item_id`, `history[].label` | целое, строка | что выпало |
| `history[].mode` | `"equal"` / `"weighted"` | режим на момент вращения |
| `history[].effective_weight` | число | вес выпавшего варианта (в режиме `equal` всегда 1) |
| `history[].total_weight` | число | сумма весов активных вариантов на момент вращения |
| `history[].probability` | число | `effective_weight / total_weight` — шанс на момент вращения |
| `history[].created_at` | строка | локальное время записи, `ГГГГ-ММ-ДДTЧЧ:ММ:СС` |
| `spin_count` | целое | сколько вращений записано за всю сессию; очистка истории его не сбрасывает |
| `created_at`, `updated_at` | строка | время создания сессии и последней записи файла |

### Что происходит при загрузке

| Файл | Поведение |
|---|---|
| версия `1` | загружается как есть |
| старый (версия 0.1.0: нет `contract_version` и `spin_count`) | загружается; `spin_count` принимается равным длине истории; при следующем сохранении файл записывается в формате версии 1. Пример: `examples/input/session_v0_legacy.json` |
| более новый (`contract_version` больше 1) | не загружается, сообщение «Файл сохранения создан более новой версией инструмента…»; файл не изменяется |
| повреждённый (пустой, обрезанный, не UTF-8, не JSON, `NaN`/`Infinity`) | не загружается, сообщение «Файл сохранения повреждён: …»; файл не изменяется |
| чужой JSON или нарушена структура (нет `items`, неизвестный режим, `active_ids` указывает на несуществующий вариант и т. п.) | не загружается, сообщение «Это не файл сохранения колеса или он повреждён: …» с названием поля |
| есть незнакомые поля | загружается; незнакомые поля игнорируются и при следующем сохранении пропадают |

Во всех случаях отказа код бросает `app.storage.save_load.SessionFormatError` с русским текстом, окно показывает его в диалоге «Autosave». Точные тексты записаны в `examples/output_expected/saved_files.json`.

Не загруженный файл остаётся на диске до тех пор, пока пользователь не откроет новое колесо (тогда autosave перезаписывается).

## Правило выбора при заданном seed

- Вес варианта: в режиме `equal` — 1; в режиме `weighted` — `value`, а если веса нет — 1.
- При `random_seed` ≠ 0 вращение с номером `n` (`n` = `spin_count` до вращения, счёт с 0) определяется так: `x = random.Random(seed * 2**32 + n).random() * сумма_весов`; выпадает первый активный вариант (в порядке `items`), у которого накопленная сумма весов больше `x`.
- Следствия: один и тот же список, режим и seed дают одну и ту же последовательность; результат не зависит от анимации и от того, была ли сессия закрыта и продолжена из autosave.
- Используется только `Random.random()` — его последовательность для заданного seed одинакова в разных версиях Python. Эталонные последовательности: `examples/output_expected/winners.json`.
- При `random_seed` = 0 используется несидированный генератор, воспроизводимость не обещается.

## Экспорт истории

Файл и формат выбирает пользователь в диалоге «Экспорт истории». Существующий файл перезаписывается. После экспорта окно показывает итог: «Готово. / Экспортировано записей: N / Результат: путь».

| Формат | Структура |
|---|---|
| JSON | объект `{"contract_version": 1, "records": [...]}`; запись — те же поля, что у `history[]` в файле сохранения. UTF-8 |
| CSV | UTF-8 с BOM, разделитель `;`, переводы строк CRLF; заголовок `index;label;mode;effective_weight;total_weight;probability;created_at`; `index` считается с 1 |
| TXT | UTF-8, строка на запись: `N. название \| mode=… \| weight=… \| p=…% \| время`. Для чтения человеком; для разбора программой берите JSON или CSV |

Эталоны: `examples/output_expected/history.json`, `history.csv`, `history.txt`.

## Что НЕ входит в контракт

- Внешний вид окон, тексты кнопок и подписей, параметры анимации (угол остановки, число оборотов).
- Python-функции и классы в `app/` — это внутренний API: импортировать можно, но имена и сигнатуры могут меняться без смены версии контракта. Исключение — поведение, описанное выше.
- Точный текст предупреждений разбора и сообщений об ошибках (их проверяет регрессия, но программам на них опираться не стоит).
- Формат строки TXT-экспорта.
- Имя временного файла при записи autosave.
