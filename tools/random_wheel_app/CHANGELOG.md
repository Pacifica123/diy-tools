# CHANGELOG

## 0.2.0

Доведение капсулы до M3 («Stable Utility»).

Добавлено:

- `docs/CONTRACT.md` — внешний контракт версии 1: запуск, файл сохранения/autosave, экспорт, правило выбора при seed.
- В файл сохранения/autosave добавлены поля `contract_version` (сейчас `1`) и `spin_count`. Файлы версии 0.1.0 по-прежнему загружаются.
- Регрессионные примеры: `examples/input/` (списки, включая файл с ошибочными строками, и записанные файлы сохранения) и `examples/output_expected/` (эталоны).
- `scripts/smoke_test.py` переписан: разбор списков, точная последовательность победителей при seed, autosave → загрузка → продолжение, история, экспорт, испорченные файлы сохранения. Пишет только во временный каталог. Ключ `--update-expected` обновляет эталоны.
- `tool.ini`: `maturity = M3`, `status = tested`, `linux = tested` (доменный слой и хранение; см. `tested_scope`), ссылки на контракт, регрессию и CHANGELOG. README: разделы «Проверка», «Контракт», «История», место хранения autosave.
- После экспорта окно показывает итог: «Готово. / Экспортировано записей: N / Результат: путь». Кнопка «Сохранить» показывает путь к autosave.

Изменено (заметно пользователю):

- JSON-экспорт истории теперь объект `{"contract_version": 1, "records": [...]}`, а не голый список записей.
- Победитель вращения при seed ≠ 0 теперь определяется парой (seed, номер вращения). Последовательности для того же seed отличаются от версии 0.1.0.
- Примеры `examples/sample_equal.txt` и `examples/sample_weighted.txt` переехали в `examples/input/`.

Исправлено:

- После «Продолжить autosave» колесо с заданным seed заново выдавало ту же последовательность, что и с начала сессии. Теперь сессия продолжается с того места, где остановилась.
- Последовательность победителей в окне зависела от случайных чисел, потраченных на анимацию, и не совпадала с тем, что даёт доменный слой при том же seed.
- Строка с двоеточием в названии и без веса (`Игра: подзаголовок`) обрезалась до текста перед двоеточием. Теперь вариантом становится вся строка.
- Значения `inf` и `nan` после двоеточия принимались за положительный вес и ломали расчёт шансов. Теперь это предупреждение и вариант без веса.
- Повреждённый или чужой файл autosave давал английский текст исключения, а чужой JSON-объект молча открывал пустое колесо. Теперь — понятная русская ошибка, файл не трогается.
- Autosave пишется через временный файл с заменой: оборванная запись больше не оставляет пустой файл.
- Запуск без PySide6 печатает русское сообщение с командой установки вместо traceback; `run.sh` и `run.bat` сообщают об отсутствии Python.

Не проверено: GUI-слой (PySide6 в среде проверки нет) и Windows.

## 0.1.0

Состояние до M3 (зрелость M2, статус `working`):

- GUI на PySide6: импорт TXT-списка, колесо в равном или взвешенном режиме, random seed, режим «удалять выпавший вариант».
- Autosave сессии и история вращений, экспорт истории в TXT, CSV и JSON.
- Доменная логика (`app/domain`) отделена от интерфейса (`app/ui`).
- Smoke-тест проверял parser, равные/взвешенные сегменты, seed и запись одного вращения без запуска GUI.
