# tools — общая полка DIY-инструментов

Полка ведётся по `DIY Tool Standard v0.2-devctl` (`../docs/diy-tool-standard/STANDARD.md`). Реестр — `../TOOLS.md`.

Каждая подпапка — самодостаточная капсула инструмента уровня M3:

```text
tools/<tool_id>/
  README.md              человеческий контракт: что делает, как запустить, что может испортить
  tool.ini               паспорт: версия, статус, зрелость, флаги риска, среды, проверки
  CHANGELOG.md           история изменений, новые версии сверху
  docs/CONTRACT.md       версионированный внешний контракт
  run.sh / run.bat       запуск
  examples/input/            регрессионные входы
  examples/output_expected/  эталоны, полученные настоящим запуском
  scripts/smoke_test.*   герметичная проверка: сравнивает результат с эталонами
```

Проверить всю полку:

```bash
python ../scripts/check_tools_shelf.py
```

Проверить одну капсулу — из любой папки:

```bash
python tools/<tool_id>/scripts/smoke_test.py
```

Правила полки:

- Сюда не кладутся `.git/`, `.devctl/`, `node_modules/`, `target/`, `dist/`, сборочные артефакты, Python bytecode, приватные отчёты и абсолютные личные пути.
- Smoke-тесты пишут только во временный каталог. Если после проверки в капсуле появился новый файл — это ошибка теста.
- В примерах намеренно есть имена с пробелами и кириллицей. Эталоны сравниваются побайтно, поэтому окончания строк в `examples/` не преобразуются (`../.gitattributes`).
- Изменения приходят devctl-патчами (`../docs/diy-tool-standard/DEVCTL_PATCH_PROTOCOL.md`).
