# Внешний контракт Markdown Splitter

Версия контракта: 1

Здесь описано то, на что может опираться другая программа или будущий автор. Та же версия записана в `tool.ini` (`[data] contract_version`), в коде (`CONTRACT_VERSION` в `src/cli.py`) и в каждом `index.json` (поле `contract_version`).

Правило: несовместимое изменение любого пункта этого документа = новая версия контракта + запись в `CHANGELOG.md`. Добавление нового необязательного поля или параметра версию не меняет.

## Вызов

```text
python src/cli.py <source> [--max-size РАЗМЕР] [--output-dir ПАПКА] [--dry-run] [--json]
sh run.sh <те же аргументы>
run.bat <те же аргументы>
```

Запускалки не меняют текущую папку: относительные пути считаются от папки, из которой запущена команда.

| Аргумент | Значение |
|---|---|
| `source` | один исходный файл; обязателен |
| `--max-size` | мягкий лимит части в байтах UTF-8: целое число или число с суффиксом `K`, `M`, `G` (кратно 1024), допускается дробь (`1.5M`); по умолчанию `1M` |
| `--output-dir` | выходная папка; должна отсутствовать или быть пустой. Без параметра — `<имя исходника>_parts` рядом с исходником, а если она уже есть — `_parts_2`, `_parts_3` и т.д. |
| `--dry-run` | ничего не создавать и не записывать, только показать план |
| `--json` | напечатать отчёт в stdout в виде JSON вместо текстовой сводки |

## Коды возврата

| Код | Когда |
|---|---|
| `0` | нарезка (или план в `--dry-run`) выполнена; предупреждения о превышении лимита код не меняют |
| `1` | ошибка обработки: файл не UTF-8, файл пуст, незакрытый fenced code block или HTML-комментарий, выходная папка не пуста или путь занят файлом, ошибка чтения/записи; также Python старше 3.11 |
| `2` | неверные аргументы или исходный файл не найден |

При коде `1` или `2` части и `index.json` не создаются.

## Вход

- Один текстовый файл в UTF-8; BOM в начале допускается и в части не переносится.
- Переводы строк `LF`, `CRLF` или `CR`. На выходе всегда `LF`.
- Ожидаемые расширения: `.md`, `.markdown`, `.mdown`, `.mkd`. Другое расширение — предупреждение в stderr, работа продолжается.
- Исходный файл только читается и никогда не изменяется.

Неделимыми блоками считаются: YAML front matter в самом начале файла, fenced code block (` ``` ` и `~~~`), таблица, blockquote, один пункт списка верхнего уровня вместе с вложенным содержимым, блок кода с отступом, HTML-комментарий, HTML-блок с явным закрывающим тегом (`details`, `summary`, `pre`, `table`, `div`, `section`, `article`, `aside`, `blockquote`), абзац, заголовок ATX или Setext.

## Выход

В выходной папке создаются только файлы частей и `index.json`.

### Части

- Имя: `NNN_<slug>.md`, где `NNN` — порядковый номер с ведущими нулями (минимум три цифры), `<slug>` — заголовок части в нижнем регистре: буквы и цифры (включая кириллицу), `-` и `_`, остальное заменено на `_` или удалено, не длиннее 80 символов; если от заголовка ничего не осталось — `part`.
- Кодировка UTF-8 без BOM, переводы строк `LF`, в конце файла перевод строки.
- Каждая часть начинается с заголовка (в первой части перед ним может стоять YAML front matter исходника).
- Граница частей проходит только между неделимыми блоками.
- Если заголовка в начале части в исходнике в этом месте не было, инструмент добавляет его сам и ставит `contextHeadingAdded = true`: это либо повтор ближайшего заголовка секции (часть-продолжение), либо синтетический `# <имя файла без расширения>` (текст до первого заголовка или документ без заголовков). Добавленный заголовок — всегда первый заголовок части.
- Если убрать добавленные заголовки и склеить части по порядку, получатся все непустые строки исходника в исходном порядке. Количество пустых строк на стыках частей не сохраняется.
- Часть больше `--max-size` возможна только тогда, когда в ней есть неделимый блок, который сам (вместе с заголовком части) не помещается в лимит. Такая часть помечена `oversized = true`, и для неё есть строка в `warnings`.

### `index.json`

Аудит-файл нарезки. UTF-8, `LF`, отступ 2 пробела, кириллица не экранируется.

| Поле | Тип | Смысл |
|---|---|---|
| `contract_version` | число | версия этого контракта, сейчас `1` |
| `formatVersion` | число | прежняя версия формата `index.json`, сохранена для совместимости, `1` |
| `source` | строка | имя исходного файла без пути |
| `maxBytes` | число | заданный лимит в байтах |
| `parts` | массив | части по порядку |
| `parts[].index` | число | номер части с 1 |
| `parts[].file` | строка | имя файла части в этой же папке |
| `parts[].title` | строка | заголовок, по которому названа часть (первый заголовок части) |
| `parts[].sizeBytes` | число | фактический размер файла части в байтах |
| `parts[].contextHeadingAdded` | логическое | первый заголовок части добавлен инструментом |
| `parts[].oversized` | логическое | `sizeBytes > maxBytes` |
| `warnings` | массив строк | по одной строке на каждую часть сверх лимита; строка начинается с `часть N ` |

Абсолютных путей и текста документа в `index.json` нет; имя исходного файла и тексты заголовков — есть.

## stdout и stderr

- С `--json`: в stdout ровно один JSON-объект — те же поля, что в `index.json`, плюс `outputDir` (путь выходной папки в том виде, как он задан или вычислен) и `dryRun`. В `--dry-run` у элементов `parts` нет поля `file`.
- Без `--json`: в stdout список частей и итоговая сводка (`Готово.`, `Обработано:`, `Создано:` или `Будет создано:`, `Предупреждений:`, `Ошибок:`, `Результат:`, `Отчёт:`).
- В stderr: строки `Ошибка: …`, сообщения о неверных аргументах, предупреждение о расширении; без `--json` — ещё и строки `Предупреждение: …` о частях сверх лимита (с `--json` они только в поле `warnings`).

## Что не входит в контракт

- Точный текст сообщений, предупреждений, справки `--help` и текстовой сводки; порядок и формат строк списка частей без `--json`.
- Где именно пройдут границы частей и сколько частей получится: эвристика может уточняться. Гарантируются только свойства из раздела «Части».
- Внутренние функции `src/cli.py` (`parse_blocks`, `split_blocks` и др.): их можно читать и менять, стабильного Python API капсула не обещает.
- Разбор всего CommonMark: конструкции вне списка неделимых блоков обрабатываются как абзацы. Определения ссылок и сноски между частями не переносятся.
