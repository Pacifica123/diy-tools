# Markdown Splitter

Статус: `draft`  
Зрелость: `M2`  
Флаги: `P, G`  
Основной интерфейс: `cli`

## Что делает

CLI режет большой UTF-8 Markdown-файл на отдельные `.md`-части так, чтобы каждая часть оставалась пригодной для самостоятельного просмотра. В отличие от исходного однофайлового скрипта, граница не ставится посреди произвольной строки после переполнения лимита.

Инструмент:

- не режет fenced code blocks (` ``` ` / `~~~`), Markdown-таблицы, blockquote и отдельные пункты списков посередине;
- распознаёт ATX- и Setext-заголовки;
- если часть продолжается внутри одной секции, повторяет ближайший заголовок в начале новой части;
- если документ начинается текстом до первого заголовка, добавляет синтетический `# <название документа>`;
- пишет части в отдельную папку и не перезаписывает непустую папку;
- создаёт `index.json` с размерами и предупреждениями.

## Зачем это исправление

Старый алгоритм проверял лимит перед каждой строкой и при переполнении просто закрывал текущую часть. Поэтому следующая часть могла начинаться с середины абзаца, списка или fenced code block. Заголовок использовался в основном для имени файла, но не как безопасная граница Markdown. В результате отдельные части могли иметь повреждённую разметку.

## Быстрый запуск

Windows:

```powershell
run.bat "D:\docs\large.md" --max-size 1M
```

Linux:

```bash
sh run.sh ./large.md --max-size 1M
```

Напрямую:

```bash
python src/cli.py ./large.md --max-size 500K
python src/cli.py ./large.md --max-size 1M --dry-run
python src/cli.py ./large.md --max-size 1M --json
```

## Вход

Один UTF-8 Markdown-файл (`.md`, `.markdown`, `.mdown`, `.mkd`). Другие расширения допускаются с предупреждением.

Размер задаётся как число байт или суффиксом `K`, `M`, `G`, включая дробное значение: `500K`, `1M`, `1.5M`.

## Выход

По умолчанию рядом с исходником создаётся новая папка:

```text
large_parts/
  001_документ.md
  002_код.md
  003_таблица.md
  index.json
```

Если `large_parts/` уже существует, выбирается `large_parts_2/`, затем `_3` и т.д. При явном `--output-dir` каталог должен отсутствовать или быть пустым.

`index.json` содержит имя исходного файла, целевой лимит, список частей, фактические размеры, признак добавленного контекстного заголовка и предупреждения.

## Почему `--max-size` мягкий

Главный приоритет — не ломать Markdown. Если один неделимый структурный блок сам больше лимита (например, огромный fenced code block или таблица), инструмент сохраняет его целиком. Такая часть отмечается `oversized=true`, а CLI печатает предупреждение.

Это намеренный компромисс: безопасная структура важнее ложной гарантии «ровно не больше N байт».

## Побочные эффекты и предупреждения

- Удаляет файлы: нет.
- Перезаписывает файлы: нет; непустой явный output-dir блокируется.
- Использует сеть: нет.
- Запускает внешние команды: нет.
- Читает потенциально приватный текст: да (`P`), но содержимое не отправляется в сеть и не попадает в отчёт.
- Генерирует новые `.md` и `index.json`: да (`G`).
- Незакрытый fenced code block считается ошибкой: инструмент не создаёт заведомо сломанные части.

## Границы применимости

Это не полный CommonMark-парсер. Инструмент защищает основные многострочные конструкции, из-за которых практическая нарезка чаще всего ломается: code fences, таблицы, blockquote, списки, HTML-блоки с явным закрытием, абзацы и заголовки.

Reference-style links и footnotes не копируются автоматически между частями. Если определение ссылки находится далеко от места использования, отдельный chunk может потерять кликабельность ссылки, хотя сама Markdown-структура останется валидной.

## Проверка

```bash
python scripts/smoke_test.py
```

Smoke-тест проверяет, что:

- каждая часть начинается с Markdown-заголовка;
- fenced code block с `#` внутри не принимается за секцию и не разрывается;
- таблица не режется посередине;
- продолжения секций получают контекстный заголовок;
- непустая выходная папка не перезаписывается;
- незакрытый fence завершается понятной ошибкой.

## Как изменить под себя

Вся логика находится в `src/cli.py`:

- `parse_blocks()` — разбор на защищённые Markdown-блоки;
- `split_blocks()` — мягкий лимит и контекстные заголовки;
- `sanitize_filename()` — переносимые имена частей;
- `write_chunks()` — запись `.md` и `index.json`.
