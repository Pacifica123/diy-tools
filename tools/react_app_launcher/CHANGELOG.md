# История изменений StartDeck (`react_app_launcher`)

Новые версии сверху. Несовместимое изменение формата конфига или отчёта пробного прогона = новая версия контракта (`docs/CONTRACT.md`) и запись здесь.

## 0.4.0

Доведение капсулы до зрелости M3. Версия контракта: 1.

Добавлено:

- `electron/launch_core.cjs` — ядро запуска без Electron: форма конфига, проверка элементов, план запуска. `electron/main.cjs` теперь берёт эту логику из ядра, поэтому её можно проверять обычным Node.js без `npm install`.
- `scripts/dry_run.js` — пробный прогон файла профилей: печатает JSON-отчёт о том, что было бы выполнено, и ничего не запускает.
- `docs/CONTRACT.md` — описание формата конфига, правил переноса старых конфигов и отчёта пробного прогона.
- `examples/input` и `examples/output_expected` — три регрессионных примера (текущий формат, старый формат-массив, проблемные элементы) с путями с пробелами и кириллицей.
- `scripts/smoke_test.js` переписан: сравнивает результат ядра, `scripts/dry_run.js` и обработчиков `main.cjs` (с заглушками Electron и `child_process`) с эталоном. Раньше тест только искал строки в исходниках.
- Открытый конфиг и отчёт пробного прогона получают поле `"contract_version": 1`. Конфиг без этого поля читается как раньше.
- `run.sh` и `run.bat` сообщают по-русски, если не найден `npm` или не выполнен `npm install`.

Исправлено:

- Ошибка старта процесса (например, программа или команда не найдена системой) больше не становится необработанным исключением главного процесса Electron: она попадает в результат элемента как «Не удалось запустить: …», остальные элементы профиля запускаются дальше.
- Элемент `null` или профиль без массива `items` в конфиге больше не обрывает проверку и запуск всего профиля: такой элемент получает статус «Некорректный элемент».
- Открытый `profiles.json` больше не игнорируется, когда системное шифрование стало доступно: он переносится в `profiles.encrypted.json` так же, как старый `apps.json`. Раньше в такой ситуации приложение открывалось с пустым списком профилей.
- В `run.bat` запуск идёт через `call npm run dev`: без `call` строки после `npm` не выполнялись и сообщение об ошибке не показывалось.

Изменилось поведение:

- Элемент с неизвестным `type` (не `app`, `folder`, `file`, `url`, `command`) теперь считается ошибкой («Неизвестный тип элемента: …») и не запускается. Раньше он молча запускался как программа. Элемент без `type` по-прежнему считается программой.
- Конфиг с `contract_version` больше 1 или не числом не читается: приложение показывает ошибку о неподдерживаемой версии.

Не проверялось: настоящее окно Electron/React, реальный запуск программ, `safeStorage`, `npm run dev`, сборка portable EXE, Windows. Подробности — README, раздел «Проверка».

## 0.3.1

Состояние до M3 (зрелость M2, статус `working`), по `BUILD_NOTES.md` и README этой версии:

- публичное имя инструмента — StartDeck, технический id капсулы остался `react_app_launcher`;
- `data/apps.json` пустой, безопасный пример вынесен в `data/example-apps.json` и в кнопку «+ Пример»;
- пользовательские профили хранятся в папке данных Electron-приложения; при доступном `safeStorage` — в `profiles.encrypted.json`, иначе в `profiles.json`;
- перенос старых конфигов из `apps.json` и старых папок данных;
- `command` запускается без shell, если в JSON явно не указано `allowShell: true`;
- зависимости закреплены конкретными версиями;
- smoke-тест проверял только наличие нужных строк в исходниках.

Более ранние заметки о сборке (0.2.2, пустое окно в portable EXE) — в `BUILD_NOTES.md`.
