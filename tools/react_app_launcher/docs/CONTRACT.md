# Контракт StartDeck (`react_app_launcher`)

Версия контракта: 1

Контракт — то, на что может опираться другая программа или будущий автор: формат JSON-конфига профилей, файлы хранения, правила переноса старых конфигов и отчёт пробного прогона `scripts/dry_run.js`.

Правило: несовместимое изменение = новая версия контракта + запись в `CHANGELOG.md`. Добавление необязательного поля версию не меняет.

Вся логика контракта реализована в `electron/launch_core.cjs` (константа `CONTRACT_VERSION`).

## Формат конфига профилей

Открытый конфиг — JSON в UTF-8:

```json
{
  "contract_version": 1,
  "profiles": [
    {
      "id": "work",
      "name": "Работа",
      "description": "Основной рабочий набор",
      "items": [
        { "id": "notes", "name": "Заметки", "type": "file", "path": "~/Документы/заметки проекта.txt" }
      ]
    }
  ]
}
```

### Верхний уровень

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `contract_version` | число | нет поля = 1 | Версия контракта. Приложение само добавляет поле при сохранении. Значение больше 1 или не число — ошибка «неподдерживаемая версия контракта», файл не читается. |
| `profiles` | массив | обязательно | Профили запуска. Если `profiles` нет или это не массив — ошибка «Конфиг должен быть объектом вида: { "profiles": [] }». |

Старая форма — массив профилей без внешнего объекта (`[ {…}, {…} ]`) — принимается и превращается в `{ "profiles": [...] }`. В такой же форме (массив) профили показывает и принимает редактор «JSON» в окне.

Другие поля верхнего уровня приложение при сохранении не сохраняет: в файл попадают только `contract_version` и `profiles`.

### Профиль

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `id` | строка | — | Идентификатор; по нему профиль ищется при запуске. Должен быть уникальным. |
| `name` | строка | — | Название в окне и в журнале. |
| `description` | строка | — | Необязательное описание. |
| `items` | массив | нет поля = пусто | Элементы запуска, выполняются по порядку. |

### Элемент

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `id` | строка | — | Идентификатор внутри профиля. |
| `name` | строка | — | Название в окне и в журнале. |
| `type` | строка | `app` | Одно из: `app`, `folder`, `file`, `url`, `command`. Регистр важен. Любое другое значение — ошибка «Неизвестный тип элемента: …», элемент не запускается. |
| `enabled` | логическое | `true` | Только точное `false` отключает элемент. Отключённый элемент не проверяется и не запускается. |
| `path` | строка | — | Путь к программе, папке, файлу или имя команды. Обязателен для всех типов, кроме `url`. |
| `url` | строка | — | Адрес. Обязателен для `url`. |
| `args` | массив строк или строка | нет аргументов | Аргументы для `app` и `command`. Строка делится по переводам строки: одна строка = один аргумент; пробелы по краям и пустые строки отбрасываются. |
| `delayMs` | число | `0` | Пауза перед элементом в миллисекундах. Отрицательное или нечисловое значение = 0. |
| `skipIfRunning` | логическое | `false` | Не запускать, если процесс уже есть. Проверка работает только в Windows (через `tasklist`); в других системах элемент запускается всегда. |
| `processName` | строка | имя файла из `path` | Имя процесса для `skipIfRunning`. |
| `allowShell` | логическое | `false` | Разрешить shell. Действует только при `type = command` и только при точном `true`. |

Подстановки в `path`: `~` в начале пути заменяется на `USERPROFILE` или `HOME`; `%ИМЯ%` — на переменную окружения. Незаданная переменная остаётся в пути как есть, и путь считается ненайденным.

Неизвестные поля элемента и профиля приложение не трогает при сохранении через редактор «JSON». Форма редактирования элемента в окне пересобирает элемент из известных ей полей (`id`, `name`, `type`, `enabled`, `delayMs`, `path` или `url`, `args`, `processName`, `skipIfRunning`); остальные поля, в том числе `allowShell`, после правки через форму пропадают. `allowShell` задаётся только через редактор «JSON».

### Что выполняется для каждого типа

| Условие | Действие (`action` в плане) |
|---|---|
| `enabled: false` | `skip`, причина `disabled` |
| `type = url` | `openExternal`: адрес передаётся системе как есть. Списка разрешённых схем нет — `steam://…` или `file://…` тоже будут переданы. |
| `type = folder` или `type = file`; также `app` и `command`, если `path` оказался папкой | `openPath`: открыть в приложении по умолчанию |
| `type = app` или `type = command` | `spawn`: запуск процесса `path` с массивом аргументов `args` |

Правила безопасности для `spawn`, на которые можно опираться:

- путь и аргументы никогда не склеиваются в одну строку: аргументы передаются отдельным массивом;
- shell выключен (`shell: false`), кроме случая `type = command` и `allowShell: true`;
- для `app`, `folder`, `file`, `url` поле `allowShell` игнорируется;
- для `app`, `folder`, `file` путь должен существовать, иначе ошибка «Файл или папка не найдены: …» до запуска;
- для `command` существование не проверяется заранее (команда может искаться в `PATH`); если система не смогла её запустить, результат элемента — ошибка «Не удалось запустить: …».

### Статус элемента (проверка до запуска)

Проверка профилей возвращает для каждого элемента:

| Поле | Смысл |
|---|---|
| `id` | `id` элемента |
| `ok` | `true`, если элемент можно запускать или он отключён |
| `kind` | `disabled`, `url`, `command`, `folder`, `file`, `app` или `unknown` |
| `issue` | Пустая строка или текст проблемы: «Отключено», «Не указан URL», «Не указан путь», «Не найдено: …», «Неизвестный тип элемента: …», «Некорректный элемент» |
| `resolvedPath` | Путь после подстановок, либо `url`, либо пустая строка |

## Где хранится конфиг

Рабочий конфиг лежит в папке данных Electron-приложения (`userData`), а не в капсуле:

| Файл | Когда используется |
|---|---|
| `profiles.encrypted.json` | системное шифрование Electron `safeStorage` доступно |
| `profiles.json` | шифрование недоступно; открытый JSON в формате выше |

`profiles.encrypted.json` — обёртка с тремя полями:

```json
{ "format": "startdeck.encrypted-config.v1", "encrypted": true, "payload": "<base64>" }
```

`payload` — открытый конфиг в формате выше, зашифрованный `safeStorage` для текущего пользователя системы. Прочитать его может только StartDeck под тем же пользователем на том же компьютере; перенести файл на другой компьютер нельзя. Поле `format` — собственная версия обёртки, она не связана с `contract_version`.

`data/apps.json` в капсуле — стартовый конфиг для первого запуска; он пустой и не должен содержать личных путей. Приложение его только читает.

### Перенос старых конфигов

Если рабочего файла ещё нет, при первом обращении берётся первый существующий файл из списка, читается как открытый конфиг и сохраняется как рабочий. Исходный файл не удаляется.

1. `<userData>/profiles.json` (имеет смысл, когда шифрование стало доступно позже)
2. `<userData>/apps.json`
3. `<appData>/App Launcher/apps.json`
4. `<appData>/react-app-launcher/apps.json`
5. `data/apps.json` из капсулы
6. пустой конфиг `{ "profiles": [] }`

Обратного переноса нет: если шифрование перестало быть доступным, `profiles.encrypted.json` не читается, а приложение начинает с шагов 2–6.

## Пробный прогон `scripts/dry_run.js`

```text
node scripts/dry_run.js <конфиг.json>
node scripts/dry_run.js --help
```

Читает открытый конфиг (объект или старый массив), ничего не запускает и ничего не записывает. Нужен только Node.js, без `npm install`. Зашифрованный `profiles.encrypted.json` не принимается.

- stdout — только JSON-отчёт;
- stderr — итог по-русски («Готово: пробный прогон, ничего не запущено.», счётчики) или сообщение «Ошибка: …».

| Код выхода | Смысл |
|---|---|
| 0 | проблемных элементов нет |
| 1 | отчёт напечатан, есть проблемные элементы |
| 2 | неверные аргументы, файл не прочитан, не JSON, неверная форма или зашифрованный конфиг; stdout пуст |

Результат зависит от компьютера: существование путей и значения переменных окружения проверяются на машине, где запущен прогон.

### Отчёт пробного прогона

```json
{
  "contract_version": 1,
  "mode": "dry-run",
  "launched": 0,
  "summary": { "profiles": 1, "items": 2, "ready": 1, "disabled": 0, "problems": 1 },
  "config": { "contract_version": 1, "profiles": [] },
  "profiles": [
    {
      "id": "work",
      "name": "Работа",
      "items": [
        {
          "id": "notes",
          "name": "Заметки",
          "status": { "id": "notes", "ok": true, "kind": "file", "issue": "", "resolvedPath": "…" },
          "delayMs": 0,
          "plan": { "action": "openPath", "target": "…" }
        }
      ]
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `contract_version` | версия контракта |
| `mode` | всегда `dry-run` |
| `launched` | всегда `0` |
| `summary` | `profiles`, `items` — количества; `ready` — есть план запуска; `disabled` — отключены; `problems` — плана нет |
| `config` | нормализованный конфиг: так он был бы записан в открытый `profiles.json` |
| `profiles[].items[].status` | статус элемента (см. выше) |
| `profiles[].items[].delayMs` | пауза перед элементом |
| `profiles[].items[].plan` | план или `null`, если элемент запустить нельзя |
| `profiles[].items[].error` | текст ошибки, только при `plan: null` |

Виды плана:

| `action` | Поля |
|---|---|
| `skip` | `reason` (`disabled`) |
| `openExternal` | `url` |
| `openPath` | `target` |
| `spawn` | `file`, `args` (массив), `options` (`detached`, `stdio`, `shell`, `windowsHide`), `skipIfRunning`, `imageName` |

Примеры входа — `examples/input/*.json`, эталонные отчёты — `examples/output_expected/*.dry_run.json` (абсолютный путь к `examples/input/fixture` заменён в них на `<EXAMPLES>`).

## Что не входит в контракт

- имена IPC-каналов и методы `window.launcherApi` (`electron/preload.cjs`) — внутренняя связь окна и главного процесса;
- вид окна, тексты кнопок и строк журнала в окне;
- файлы `examples/output_expected/*.stub_launch.json` — формат только для smoke-теста;
- тексты сообщений об ошибках (кроме того, что они на русском);
- точное имя папки `userData` — его определяет Electron и сборщик;
- поведение запущенных программ и то, что система сделает с URL или файлом.
