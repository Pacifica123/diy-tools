# StartDeck

Статус: `working`  
Зрелость: `M3`  
Флаги: `O, P`  
Основной интерфейс: `gui/electron`  
Технический ID капсулы: `react_app_launcher`  
Версия: `0.4.0`, версия контракта: `1`

**StartDeck** — локальный React + Electron лаунчер профилей. Он запускает выбранный набор программ, папок, файлов, сайтов и команд одной кнопкой.

Статус `working`, а не `tested`: автоматически проверяются ядро запуска и формат конфига, но главный процесс Electron в версии 0.4.0 был переписан на это ядро без запуска окна. Перед тем как полагаться на 0.4.0, один раз выполните `npm install`, `npm run dev` и проверьте запуск профиля — см. раздел «Проверка».

## Когда использовать

Когда часто приходится открывать один и тот же набор программ, папок и ссылок для работы, учёбы, игры, записи видео или диагностики ПК.

## Быстрый запуск

Режим разработки (нужны Node.js 20+ и один раз `npm install`):

```bash
npm install
npm run dev
```

То же самое делают `run.sh` и `run.bat`. Если `npm` не найден или `npm install` ещё не выполнен, они сообщают об этом и ничего не запускают.

Сборка Windows portable EXE (собранное приложение запускается двойным кликом, Node.js для него не нужен):

```bash
npm run dist:win
```

Пробный прогон файла профилей без окна и без `npm install` — показывает, что было бы выполнено, и ничего не запускает:

```bash
node scripts/dry_run.js examples/input/01_current_format.json
```

## Вход

Профили запуска имеют JSON-формат:

```json
{
  "contract_version": 1,
  "profiles": [
    {
      "id": "work",
      "name": "Работа",
      "description": "Основной рабочий набор",
      "items": []
    }
  ]
}
```

Поддерживаемые типы элементов:

- `app` — программа;
- `folder` — папка;
- `file` — файл через приложение по умолчанию;
- `url` — сайт;
- `command` — внешний исполняемый файл или команда.

Элемент с любым другим `type` считается ошибкой и не запускается.

Raw shell-команды отключены по умолчанию. Для них нужно вручную указать `allowShell: true` в редакторе «JSON». Это намеренное ограничение, потому что профиль запуска фактически является списком локальных действий. Аргументы всегда передаются программе отдельным списком и не склеиваются в командную строку.

Все поля, значения по умолчанию и правила переноса старых конфигов — в [docs/CONTRACT.md](docs/CONTRACT.md).

## Выход

GUI показывает профили, статусы путей (несуществующие пути видны до запуска), путь к текущему конфигу и журнал запуска. При запуске профиля возвращается результат по каждому элементу: успешно, пропущено или ошибка.

`scripts/dry_run.js` печатает JSON-отчёт в stdout и итог в stderr; код выхода `0` — проблем нет, `1` — есть проблемные элементы, `2` — конфиг не прочитан.

### Журнал запусков и ошибок

Журнал ведётся в окне, в панели «Журнал запуска»: строки «Запускаю профиль», «ОК», «Пропуск», «Ошибка» с временем, а также ошибки загрузки и сохранения конфига. Он хранит последние 90 записей, живёт только в памяти окна и пропадает при закрытии приложения. В файл журнал не пишется намеренно: в нём есть названия и пути из профилей, а конфиг рядом хранится зашифрованным.

## Конфиги и приватность

В репозитории и devctl-патче нет личных путей.

`data/apps.json` в капсуле специально пустой и должен таким оставаться — это только стартовый конфиг для первого запуска:

```json
{
  "profiles": []
}
```

Безопасный пример лежит отдельно: `data/example-apps.json` (все элементы отключены).

Рабочие профили сохраняются не в капсуле, а в папке данных Electron-приложения:

| Режим | Папка |
|---|---|
| собранное приложение, Windows | `C:\Users\<user>\AppData\Roaming\StartDeck\` |
| `npm run dev`, Windows | `C:\Users\<user>\AppData\Roaming\startdeck\` — для Windows это та же папка, регистр букв не различается |
| Linux (не проверялось) | `~/.config/StartDeck/` или `~/.config/startdeck/` |

Имя папки выбирает Electron, здесь оно не проверялось. Точный путь всегда показан в окне (карточка с путём конфига) и открывается кнопкой «Открыть конфиг».

Файл в этой папке:

- `profiles.encrypted.json` — если доступно системное шифрование Electron `safeStorage`. Содержимое зашифровано для текущего пользователя системы: файл нельзя прочитать глазами, перенести на другой компьютер или открыть под другим пользователем. Для переноса профилей скопируй их текст из редактора «JSON» в окне.
- `profiles.json` — открытый JSON, если шифрование недоступно.

Обновление или удаление капсулы рабочий конфиг не затрагивает.

## Побочные эффекты и предупреждения

- Удаляет файлы: нет.
- Перезаписывает файлы: да, пользовательский конфиг профилей при сохранении.
- Использует сеть: не сам; но может открыть URL в браузере. Адрес передаётся системе как есть, схема не проверяется.
- Запускает внешние команды: да.
- Может содержать приватные данные: да, пользовательский конфиг хранит пути и привычки запуска.

Флаг `O` означает, что к профилям нужно относиться как к исполняемым действиям. Тип `command` опаснее `app`, `folder`, `file` и `url`.

Известное ограничение: форма редактирования элемента в окне не знает про `allowShell`. Если изменить через форму элемент с `allowShell: true`, поле пропадёт и команда будет запускаться без shell. Верни его в редакторе «JSON».

## Проверка

```bash
node scripts/smoke_test.js
```

Тест не требует `npm install`, пишет только во временную папку и ничего не запускает.

Что проверяется:

- три примера из `examples/input` (текущий формат, старый формат-массив, проблемные элементы; пути с пробелами и кириллицей) проходят через ядро `electron/launch_core.cjs` и через `scripts/dry_run.js`, результат сравнивается с `examples/output_expected/*.dry_run.json`;
- те же примеры сохраняются, проверяются и «запускаются» через обработчики `electron/main.cjs`, где Electron и запуск процессов заменены заглушками; результат сравнивается с `examples/output_expected/*.stub_launch.json`;
- правила безопасности: shell включается только для `command` с точным `allowShell: true`, аргументы остаются отдельным списком, неизвестный тип и отсутствующий путь дают ошибку, отключённые элементы пропускаются;
- хранение: первый запуск создаёт конфиг во временной папке данных, `data/apps.json` остаётся пустым, перенос старого `apps.json` и открытого `profiles.json`, обёртка `profiles.encrypted.json` (с поддельным шифрованием), отказ читать конфиг более новой версии;
- согласованность `package.json`, `tool.ini`, `CHANGELOG.md`, `docs/CONTRACT.md`, IPC-каналов между `src/App.jsx`, `electron/preload.cjs` и `electron/main.cjs`.

Что НЕ проверялось:

- настоящее окно Electron и интерфейс React: приложение в этой версии не запускалось ни через `npm run dev`, ни в собранном виде;
- сборка portable EXE (`npm run dist:win`) после вынесения ядра в `electron/launch_core.cjs`; файл попадает в сборку по правилу `electron/**/*` из `package.json`, но сама сборка не выполнялась;
- реальный запуск программ, открытие папок, файлов и URL;
- настоящее шифрование `safeStorage`;
- Windows: автоматическая проверка шла только на Linux; `run.bat` не запускался.

Перед тем как полагаться на версию 0.4.0, один раз пройди вручную: `npm install`, `npm run dev`, создать профиль, запустить элемент, перезапустить приложение и убедиться, что профили на месте; перед релизом — `npm run dist:win` и запуск собранного EXE.

## Как пользоваться

1. Запусти StartDeck.
2. Создай профиль, например `Работа`.
3. Нажми `+ Добавить`.
4. Выбери тип элемента: программа, папка, файл, сайт или команда.
5. Для программы, папки или файла нажми `Выбрать`, чтобы не писать путь вручную.
6. Укажи имя процесса, если нужна защита от повторного запуска (работает только в Windows).
7. Включи или отключи нужные элементы тумблером.
8. Нажми `Запустить всё`.

## Как изменить под себя

- UI: `src/App.jsx`, `src/styles.css`.
- Логика запуска и формат конфига: `electron/launch_core.cjs`.
- Electron main process (окно, хранение, шифрование, IPC): `electron/main.cjs`.
- IPC contract: `electron/preload.cjs`.
- Стартовый пустой config: `data/apps.json`.
- Безопасный пример: `data/example-apps.json`.
- После осознанного изменения логики запуска пересоздай эталоны: `node scripts/smoke_test.js --write-expected`, просмотри разницу в `examples/output_expected` и снова запусти `node scripts/smoke_test.js`.

## Граница применимости

Инструмент не является sandbox. Всё, что пользователь добавил в профиль запуска, будет выполняться локальной машиной. Перед запуском чужого JSON-профиля его нужно просмотреть вручную или прогнать через `node scripts/dry_run.js`.
