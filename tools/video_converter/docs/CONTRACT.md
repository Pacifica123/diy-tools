# Внешний контракт video_converter

Версия контракта: 1

Контракт — это то, на что может опираться другая программа или будущий автор: способ вызова, аргументы, коды возврата и формат JSON-отчёта. Версия записана в `tool.ini` (`[data] contract_version`), в `src/cli.py` (`CONTRACT_VERSION`) и в каждом JSON-отчёте (`"contract_version": 1`).

Правило: несовместимое изменение = новая версия контракта + запись в `CHANGELOG.md`. Добавление нового необязательного аргумента или нового поля в отчёт несовместимым изменением не считается.

## Вызов

```text
python src/cli.py <папка> [--recursive] [--output-dir ПАПКА] [--overwrite]
                          [--delete-originals] [--dry-run] [--ffmpeg КОМАНДА] [--report ФАЙЛ]
```

Лаунчеры `run.sh` и `run.bat` передают аргументы как есть и не меняют текущую папку, поэтому относительные пути считаются от папки, из которой запущена команда.

| Аргумент | Смысл |
|---|---|
| `<папка>` | Папка с `.mkv`. Обязательна. |
| `--recursive` | Искать `.mkv` и во вложенных папках. |
| `--output-dir ПАПКА` | Складывать `.mp4` в эту папку, сохраняя структуру вложенных папок. Без аргумента `.mp4` создаётся рядом с `.mkv`. |
| `--overwrite` | Разрешить замену уже существующего `.mp4`. Без него такой файл пропускается. |
| `--delete-originals` | Удалить `.mkv` после успешной конвертации именно этого файла. |
| `--dry-run` | Только показать план: ffmpeg не запускается, файлы не создаются, не перезаписываются и не удаляются (кроме самого отчёта, если указан `--report`). |
| `--ffmpeg КОМАНДА` | Имя команды в PATH или путь к исполняемому файлу ffmpeg. По умолчанию `ffmpeg`. |
| `--report ФАЙЛ` | Записать JSON-отчёт в этот файл (существующий отчёт заменяется). |

## Вход

- Папка с файлами, имя которых заканчивается на `.mkv`. На файловых системах, различающих регистр (Linux), файлы `.MKV` не подхватываются.
- Без `--recursive` берутся только файлы верхнего уровня.
- Содержимое файлов инструмент сам не читает — их читает ffmpeg.
- Пути с пробелами и кириллицей поддерживаются.

## Выход

- Для `видео/имя.mkv` создаётся `видео/имя.mp4`, а с `--output-dir выход` — `выход/<тот же относительный путь>/имя.mp4`.
- Пока ffmpeg работает, рядом с будущим результатом лежит временный файл `имя.vc-partial.mp4`. После успеха он становится `имя.mp4`, после ошибки удаляется. Поэтому недописанного `имя.mp4` не остаётся, а существующий `имя.mp4` при неудачной перезаписи сохраняется прежним.
- Оригинал удаляется только при `--delete-originals` и только если ffmpeg завершился с кодом 0 и выходной файл существует и не пуст.
- Backup не создаётся. Перезаписанный `.mp4` и удалённый `.mkv` восстановить средствами инструмента нельзя.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Ошибок нет (в том числе «файлов `.mkv` не найдено» и dry-run). |
| `1` | Хотя бы один файл получил статус `error`. Остальные файлы обработаны. |
| `2` | Запуск невозможен: папка не найдена, ffmpeg не найден (не в dry-run) или неверные аргументы. Ничего не изменено, отчёт не пишется. |

## stdout и stderr

- stdout: по одной строке на файл `<status>: <исходный файл> -> <выходной файл> | <сообщение>`, затем итоговая сводка: `Готово.`, `Найдено`, `Запланировано` (только в dry-run), `Создано`, `Пропущено`, `Удалено оригиналов`, `Ошибок`, `Dry-run`, `Результат`, `Отчёт` (если указан `--report`).
- stderr: сообщения `Ошибка: …` для кода 2 и предупреждение, если `--delete-originals` указан без `--report`.
- Вывод самого ffmpeg не показывается; при сбое в сообщение попадает его код возврата и последняя строка его stderr.

Для разбора программой используйте JSON-отчёт, а не stdout.

## JSON-отчёт

UTF-8, один объект:

```json
{
  "contract_version": 1,
  "summary": {
    "found": 3, "planned": 0, "created": 2, "skipped": 1,
    "deleted": 0, "errors": 0, "dry_run": false
  },
  "results": [
    {
      "source": "/абсолютный/путь/клип.mkv",
      "output": "/абсолютный/путь/клип.mp4",
      "status": "created",
      "message": "ok",
      "deleted_original": false
    }
  ]
}
```

`summary`:

| Поле | Тип | Смысл |
|---|---|---|
| `found` | число | Сколько `.mkv` найдено. |
| `planned` | число | Сколько файлов было бы сконвертировано (только dry-run). |
| `created` | число | Сколько `.mp4` создано или перезаписано. |
| `skipped` | число | Сколько пропущено, потому что `.mp4` уже есть и нет `--overwrite`. |
| `deleted` | число | Сколько оригиналов удалено. |
| `errors` | число | Сколько файлов со статусом `error`. |
| `dry_run` | логическое | Был ли это dry-run. |

`results` — по одной записи на найденный `.mkv`, в порядке сортировки путей:

| Поле | Тип | Смысл |
|---|---|---|
| `source` | строка | Абсолютный путь к `.mkv`. |
| `output` | строка | Абсолютный путь к `.mp4` (существующему, созданному или планируемому). |
| `status` | строка | `planned`, `created`, `skipped` или `error`. |
| `message` | строка | Пояснение для человека. |
| `deleted_original` | логическое | Удалён ли оригинал. |

Если `--delete-originals` указан, а удалить оригинал после успешной конвертации не получилось, запись остаётся `created` с `deleted_original: false` и пояснением в `message`.

## Приватные данные

Отчёт и stdout содержат абсолютные пути и имена медиафайлов. Содержимое файлов, метаданные видео и полный вывод ffmpeg никуда не записываются; в `message` при ошибке попадает только последняя строка stderr ffmpeg, в которой тоже может быть имя файла. Сеть не используется, других логов и файлов состояния инструмент не создаёт. Перед тем как кому-то передавать отчёт, просмотрите его.

## Что не входит в контракт

- Точные тексты `message`, сообщений об ошибках, справки `--help` и предупреждений.
- Точные параметры вызова ffmpeg (сейчас `-c:v libx264 -c:a aac`), качество и размер результата. Гарантируется только, что исходный файл передаётся после `-i`, а путь результата — последним аргументом.
- Имя временного файла `*.vc-partial.mp4`.
- Порядок ключей в JSON и точные правила сортировки путей на разных ОС.
- Функции внутри `src/cli.py`: их можно импортировать, но стабильным считается только CLI и отчёт.
