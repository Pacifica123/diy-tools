# logheaderparser

Статус: `working`  
Зрелость: `M3`  
Флаги: `S, P`  
Основной интерфейс: `cli`  
Версия: `0.2.0`

## Что делает

Rust CLI для потокового поиска шаблонов в больших логах. Инструмент читает файл построчно, заменяет переменные части (время, IP, числа, идентификаторы, пути) метками и группирует похожие строки в шаблоны.

## Когда использовать

Когда есть большой неизвестный лог и нужно быстро понять, из каких типов строк он состоит, не загружая файл целиком в память.

## Быстрый запуск

Linux:

```bash
sh run.sh examples/input/sample.log --json report.json --progress-lines 0
```

Windows:

```powershell
run.bat examples\input\sample.log --json report.json --progress-lines 0
```

Напрямую:

```bash
cargo run -- examples/input/sample.log --json report.json --top 10 --progress-lines 0
```

Лаунчеры не меняют текущую папку: относительные пути считаются от места, где запущена команда.

## Вход

Один текстовый лог-файл. Для больших файлов используйте `--progress-lines`, `--max-patterns`, `--examples` и `--threshold`. Все аргументы и правила разбора — в `docs/CONTRACT.md`.

## Выход

- stdout: сводка `Готово.` — число строк, байт и шаблонов, самые частые шаблоны, путь к отчёту;
- JSON-отчёт через `--json`, если указан путь.

JSON-отчёт содержит путь к исходному файлу и примеры строк лога. Поэтому инструмент помечен флагом `P`. С `--examples 0` строки лога в отчёт не попадают.

## Побочные эффекты и предупреждения

- Удаляет файлы: нет.
- Перезаписывает файлы: да, если `--json` указывает на существующий файл.
- Использует сеть: нет (сеть нужна только cargo при первой сборке, чтобы скачать зависимости).
- Запускает внешние команды: нет.
- Может содержать приватные данные: да, отчёт включает путь и примеры строк.

## Проверка

```bash
python scripts/smoke_test.py
```

Если `cargo` доступен, smoke-тест:

- собирает инструмент во временный каталог (в `target/` капсулы ничего не пишется) с `--locked`;
- прогоняет три регрессионных сценария на `examples/input` и сравнивает JSON-отчёты с `examples/output_expected` целиком: обычный режим на двух логах, режим `--max-patterns 3 --examples 0` (лимит шаблонов и отчёт без строк лога);
- проверяет, что прогресс идёт в stderr, а отсутствующий файл даёт понятную ошибку и ненулевой код.

Если `cargo` недоступен, проверяются только исходники, паспорт и эталоны, и тест прямо пишет, что сборка и регрессия пропущены.

Чего проверка не покрывает: Windows и `run.bat`, действительно большие логи, скорость.

Честная оговорка к версии 0.2.0: её автор не мог собрать Rust-код (не было доступа к crates.io). Правки исходника — только тексты сообщений и поле `contract_version`, эталоны выведены из алгоритма. Первая настоящая сборка и сверка происходят у владельца; до неё статус — `working`, Linux — `expected`.

Чтобы повторные прогоны шли быстрее, задайте `CARGO_TARGET_DIR` на каталог вне капсулы: тест использует его вместо временного.

## Как изменить под себя

- Токенизация и нормализация: `normalize_token` в `src/main.rs`.
- Алгоритм похожести: `similarity`.
- Лимиты памяти и примеров: аргументы `--max-patterns`, `--examples`.
- После изменения алгоритма эталоны в `examples/output_expected` пересоздаются запуском инструмента на `examples/input` с теми же аргументами, что в `scripts/smoke_test.py`; поле `file` в эталоне — `<input>/<имя файла>`.

## Граница применимости

Алгоритм эвристический: он помогает увидеть повторяющиеся шаблоны, но не гарантирует идеальную кластеризацию. Сравниваются только строки с одинаковым числом токенов. Если содержимое лога нельзя сохранять, запускайте с `--examples 0`.
