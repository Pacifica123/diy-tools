# Anime Rerank Tournament

Статус: `tested`  
Зрелость: `M3`  
Флаги: `I`  
Основной интерфейс: `gui`

## Что делает

Десктопная программа для турнирной переоценки списка аниме-тайтлов. Пользователь сравнивает пары, инструмент ведёт турнир, строит итоговый рейтинг и экспортирует новые оценки.

## Когда использовать

Когда старый список оценок нужно пересобрать через ручные попарные сравнения, а результат должен быть объяснимым: с историей матчей, scoring rules, undo и autosave.

## Быстрый запуск

Windows:

```powershell
run.bat
```

Linux:

```bash
sh run.sh
```

Напрямую:

```bash
python main.py
```

Перед первым GUI-запуском:

```bash
python -m pip install -r requirements.txt
```

Если PySide6 не установлена, программа не падает с traceback, а печатает эту команду и завершается с кодом 1.

## Вход

TXT-файл списка тайтлов. Примеры: `examples/input/sample_input.txt` и `examples/input/список с пробелами и кириллицей.txt` (дубликаты, пропущенные оценки, ошибочные строки). Формат и разбор особых случаев описаны в `docs/input_format.md`.

Базовая форма записи:

```text
1	Название
	10	12/12	Сериал
```

## Выход

Итоговый рейтинг, новые оценки, JSON/CSV/TXT export и JSON-история матчей — в файлы, которые пользователь выбирает в диалоге. После экспорта окно показывает итог: «Готово. / Записано тайтлов: N / Ошибок: 0 / Результат: путь». Примеры экспортов: `examples/output_expected/`.

Autosave сохраняет прогресс после каждого выбора, пропуска и отмены в `~/.anime_rerank_tournament/autosave.json` (домашний каталог пользователя; внутри папки инструмента ничего не сохраняется). Слот один: старт нового турнира перезаписывает прежний autosave.

Как из выборов получаются места и оценки — `docs/scoring_rules.md`.

## Побочные эффекты и предупреждения

- Удаляет файлы: нет.
- Перезаписывает файлы: autosave `~/.anime_rerank_tournament/autosave.json` (при старте нового турнира — без вопроса) и файл экспорта, выбранный пользователем.
- Использует сеть: нет.
- Запускает внешние команды: нет.
- Может содержать приватные данные: возможно, если пользовательский список приватен.

## Проверка

```bash
python scripts/smoke_test.py
```

Тест запускается из любого каталога, требует только стандартную библиотеку Python и пишет только во временный каталог (ни в папку инструмента, ни в пользовательский autosave). Он прогоняет настоящие `app/domain`, `app/storage` и `app/utils` на файлах из `examples/input/` и сравнивает результат с эталонами в `examples/output_expected/`.

Что проверяется:

- разбор TXT: обычный пример и файл с особыми случаями (кириллица, дубликаты, дробные оценки, запись без оценки, оборванная запись, посторонние строки), UTF-8 с BOM, Windows-1251, путь с пробелами и кириллицей;
- шесть коротких сценарных сессий в лайтовом и хардовом режимах: выбор, пропуск пары, отмена (состояние после отмены равно состоянию до выбора), autosave → загрузка → состояние совпадает → продолжение даёт тот же результат, что сессия без перезапуска;
- итоговый рейтинг и экспорт в TXT, CSV, JSON и история матчей — сравнение с эталонными файлами;
- правила из `docs/scoring_rules.md`: независимый пересчёт оценок обоих режимов для каждого размера списка от 1 до 1300;
- записанные файлы сохранения (`examples/input/session_v1.json` и файл версии 0.1.0): загрузка, отмена, продолжение; повреждённые, чужие и более новые файлы дают только понятную русскую ошибку, файл не изменяется;
- запуск `main.py` без PySide6 даёт сообщение с командой установки и код 1.

Что НЕ проверяется:

- GUI-слой (`app/ui`, PySide6): окна и диалоги не запускались — у файлов проверен только синтаксис. Окно проверяется вручную: запустить, импортировать `examples/input/sample_input.txt`, сделать 2–3 выбора, отмену, закрыть, «Продолжить autosave», довести до конца, экспортировать;
- Windows: статус `expected`, никто не запускал;
- `run.sh` / `run.bat` автоматически не запускаются.

Проверено на Linux с Python 3.11, 3.12 и 3.13: пары при одном seed и все эталоны совпадают на всех трёх.

После осознанного изменения поведения эталоны пересоздаются командой `python scripts/smoke_test.py --write-expected ПАПКА_ВНЕ_КАПСУЛЫ`, просматриваются и копируются в `examples/output_expected/` (плюс запись в `CHANGELOG.md`).

## Контракт

Внешний контракт — `docs/CONTRACT.md`, версия контракта: 1. В нём описаны запуск и коды возврата, файл сохранения/autosave (поля, поле версии `contract_version`, поведение на старых, более новых и повреждённых файлах), файлы экспорта и воспроизводимость пар при seed. Формат входного TXT — `docs/input_format.md`. Несовместимое изменение = новая версия контракта + запись в `CHANGELOG.md`.

## Как изменить под себя

- Parser: `app/domain/parser.py`.
- Турнир: `app/domain/tournament.py`.
- Scoring: `app/domain/scoring*.py` и `docs/scoring_rules.md`.
- Сохранение и место autosave: `app/storage/`.
- UI: `app/ui/`.

После изменения поведения запустите smoke-тест: расхождение с эталонами он покажет в виде diff.

## Граница применимости

Рейтинг является эвристикой по ручным выборам пользователя. Инструмент не доказывает объективное качество тайтлов и не должен использоваться как автоматический скорер без ручной проверки.
