# Внешний контракт Anime Rerank Tournament

Версия контракта: 1

Здесь описано то, на что может опираться другая программа или будущий автор: запуск, формат входа, файл сохранения/autosave, файлы экспорта и воспроизводимость пар при заданном seed.

Правило: несовместимое изменение любого пункта = новая версия контракта + запись в `CHANGELOG.md`. Совместимое дополнение (новое необязательное поле) версию не меняет.

## Запуск

| Что | Значение |
|---|---|
| Команда | `python main.py` (или `run.bat` / `sh run.sh`) |
| Аргументы | нет; аргументы командной строки передаются в Qt как есть |
| Код возврата `0` | окно закрыто штатно |
| Код возврата `1` | не найдена библиотека PySide6; в stderr — русское сообщение с командой установки |
| Код возврата `127` (`run.sh`) | не найден `python3` |
| stdout / stderr | при обычной работе пусто; итоги и ошибки показываются в окне |

CLI у инструмента нет. `python scripts/smoke_test.py` — проверка, а не рабочий режим.

## Вход

TXT-список тайтлов. Формат и разбор «плохих» строк: [input_format.md](input_format.md).

## Файл сохранения / autosave

Один файл на пользователя: `~/.anime_rerank_tournament/autosave.json` (домашний каталог — `Path.home()`; в Windows это `C:\Users\<имя>\`). Внутри капсулы инструмент ничего не сохраняет. Другого файла сохранения у программы нет: кнопка «Сохранить» пишет в тот же autosave.

- Записывается при старте турнира, после каждого выбора, пропуска пары, отмены, по кнопке «Сохранить» и при открытии окна результатов (тогда в нём уже есть новые оценки).
- Слот один: старт нового турнира перезаписывает прежний autosave, в том числе тот, который не удалось прочитать. Если прежняя сессия нужна — скопируйте файл заранее.
- Запись идёт через соседний временный файл `autosave.json.tmp` с последующей заменой, поэтому оборванная запись не портит прежнее сохранение.
- Кодировка UTF-8, JSON с отступом 2, кириллица не экранируется.

Примеры: `examples/input/session_v1.json` (текущий формат) и `examples/input/session_v0_legacy.json` (записан версией 0.1.0).

| Поле | Тип | Смысл |
|---|---|---|
| `contract_version` | целое | версия этого формата; сейчас `1` |
| `kind` | строка | всегда `"anime_rerank_tournament.save"`; по нему отличается чужой файл |
| `items` | список объектов | все тайтлы турнира в порядке входного файла; не пустой |
| `items[].id` | целое | номер участника внутри турнира, уникален, с 1 |
| `items[].source_index` | целое | номер записи из входного файла (может повторяться) |
| `items[].title`, `episodes`, `type` | строка | как во входном файле |
| `items[].old_score` | число или `null` | старая оценка |
| `items[].comment` | строка или `null` | комментарий из входного файла |
| `items[].wins`, `losses`, `bye_count` | целое | победы, поражения, проходы без пары |
| `items[].eliminated_round` | целое или `null` | раунд, в котором тайтл выбыл; `null` — ещё в турнире или победитель |
| `items[].lost_to_id` | целое или `null` | `id` тайтла, которому проиграл |
| `items[].new_score` | целое или `null` | новая оценка; появляется после открытия окна результатов |
| `active_ids` | список целых | участники текущего раунда; у завершённого турнира — один победитель |
| `eliminated_ids` | список целых | выбывшие, в порядке выбывания |
| `round_winner_ids` | список целых | победители уже сыгранных пар текущего раунда (включая проход без пары) |
| `round_number` | целое | номер текущего раунда, с 1 |
| `current_matches` | список матчей | пары текущего раунда в порядке показа |
| `completed_matches` | список матчей | вся история: сыгранные пары и проходы без пары, от старых к новым |
| `random_seed` | целое | seed турнира |
| `mode` | `"light"` / `"hard"` | режим оценивания, см. [scoring_rules.md](scoring_rules.md) |
| `status` | `"in_progress"` / `"finished"` | состояние турнира (`"not_started"` допустимо, но программой не пишется) |
| `created_at`, `updated_at` | строка | локальное время `ГГГГ-ММ-ДДTЧЧ:ММ:СС` |
| `undo_stack` | список объектов | снимки состояния перед каждым выбором (не больше 100 последних); каждый снимок — те же поля, кроме `contract_version`, `kind` и `undo_stack` |

Матч (элемент `current_matches`, `completed_matches` и файла истории матчей):

| Поле | Тип | Смысл |
|---|---|---|
| `id` | строка | случайный идентификатор (uuid4); между запусками не повторяется |
| `round_number` | целое | раунд |
| `left_id`, `right_id` | целое; `right_id` может быть `null` | `id` левого и правого тайтла; `null` — прохода без пары |
| `winner_id`, `loser_id` | целое или `null` | результат; `null` — пара ещё не сыграна (у прохода без пары `loser_id` всегда `null`) |
| `is_bye` | `true` / `false` | проход без пары (нечётное число участников) |
| `created_at`, `resolved_at` | строка; `resolved_at` может быть `null` | время создания и выбора |

### Что происходит при загрузке

| Файл | Поведение |
|---|---|
| версия `1` | загружается как есть; повторная запись даёт тот же файл |
| старый (версия 0.1.0: нет `contract_version` и `kind`) | загружается; списки `round_winner_ids` и `eliminated_ids` (в том числе в `undo_stack`) пересчитываются по истории матчей, потому что версия 0.1.0 портила их при отмене выбора; при следующем сохранении файл записывается в формате версии 1 |
| более новый (`contract_version` больше 1) | не загружается, сообщение «Сохранение создано более новой версией программы: …»; файл не изменяется |
| повреждённый (пустой, обрезанный, не UTF-8, не JSON, `contract_version` не целое число) | не загружается, сообщение «Сохранение повреждено: …» с причиной; файл не изменяется |
| чужой JSON (не объект, нет списка `items`, другой `kind`) | не загружается, сообщение «Это не сохранение турнира: …» |
| нарушена структура (нет обязательного поля, неизвестный `mode`/`status`, ссылка на несуществующий тайтл, списки не сходятся с историей матчей, тайтл дважды в одном раунде, выбывший тайтл снова в паре, незавершённый турнир без открытой пары) | не загружается, сообщение «Сохранение повреждено: … Причина: …» |
| файла нет | сообщение «Файл сохранения не найден: …» |
| есть незнакомые поля | загружается; незнакомые поля игнорируются и при следующем сохранении пропадают |

Во всех случаях отказа код бросает `app.utils.errors.SaveFileError` с русским текстом и путём к файлу; окно показывает его в диалоге «Autosave». Сохранение версии 0.1.0, в котором после отмены турнир уже ушёл в следующий раунд с задвоенным участником, восстановить нельзя — оно отклоняется как повреждённое.

## Экспорт

Файлы пишутся туда, куда укажет пользователь в диалоге; существующий файл перезаписывается после подтверждения в диалоге. После экспорта окно показывает итог: «Готово. / Записано тайтлов (матчей): N / Ошибок: 0 / Результат: путь».

Эталонные экспорты: `examples/output_expected/<сценарий>/`.

### Рейтинг, JSON (`ranking.json`)

UTF-8, отступ 2. Объект:

| Поле | Смысл |
|---|---|
| `contract_version` | `1` |
| `kind` | `"anime_rerank_tournament.ranking"` |
| `items` | список мест от лучшего к худшему |
| `items[].rank` | место, с 1, без пропусков и без делёжа мест |
| `items[].source_index`, `title`, `old_score`, `episodes`, `type`, `comment` | как во входном файле |
| `items[].new_score` | новая оценка (целое) |
| `items[].delta` | `new_score - old_score` (дробное число) или `null`, если старой оценки нет |
| `items[].wins`, `losses`, `bye_count` | победы, поражения, проходы без пары |
| `items[].eliminated_round` | раунд выбывания; `null` у победителя |
| `items[].lost_to` | название тайтла, которому проиграл; `null` у победителя |

### Рейтинг, CSV (`ranking.csv`)

UTF-8 с BOM, разделитель `;`, строки заканчиваются CRLF, первая строка — заголовок. Столбцы те же и в том же порядке, что поля `items[]` в JSON; `null` записывается пустой ячейкой. Многострочный комментарий остаётся одной ячейкой в кавычках.

### Рейтинг, TXT (`ranking.txt`)

UTF-8, для чтения человеком: место, название, старая и новая оценка, разница, эпизоды, тип; ниже — в каком раунде и кому проиграл, комментарий. Точная разметка строк контрактом не является — для программ есть JSON и CSV.

### История матчей, JSON (`matches.json`)

Объект `{"contract_version": 1, "kind": "anime_rerank_tournament.matches", "matches": [...]}`; `matches` — список матчей (поля см. выше) в порядке, в котором они были сыграны, включая проходы без пары.

## Воспроизводимость при заданном seed

- Пары раунда `r` получаются так: `rng = random.Random(seed + r * 10003)`, участники раунда перемешиваются `rng.shuffle`; при нечётном числе один тайтл проходит без пары (`rng.choice` среди тех, у кого проходов меньше всего и кто не проходил без пары в прошлом раунде); остальные идут парами подряд.
- Следствие: один и тот же список, seed и одни и те же выборы дают одни и те же пары, рейтинг и оценки — в том числе после закрытия программы и «Продолжить autosave». Это проверено на Python 3.11, 3.12 и 3.13.
- Пропуск пары переносит её в конец раунда и на состав пар не влияет. Отмена возвращает состояние перед последним выбором.
- Seed `0` — обычный seed, а не «случайный»; случайное значение подставляет окно при запуске.

## Что не входит в контракт

- Внешний вид окон, тексты кнопок и подписей.
- Имена и сигнатуры функций в `app/` (внутренний API; им пользуется smoke-тест, но совместимость между версиями не обещана).
- Значения `id` матчей и меток времени.
- Точная разметка `ranking.txt` и тексты сообщений об ошибках дальше их первой фразы.
- Место autosave может измениться только с записью в `CHANGELOG.md`.
