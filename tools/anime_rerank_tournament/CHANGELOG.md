# CHANGELOG

## 0.2.0

Доведение капсулы до M3 («Stable Utility»).

Добавлено:

- `docs/CONTRACT.md` — внешний контракт версии 1: запуск, файл сохранения/autosave, экспорт, воспроизводимость при seed.
- В файл сохранения/autosave добавлены поля `contract_version` (сейчас `1`) и `kind`. Файлы версии 0.1.0 по-прежнему загружаются.
- Регрессионные примеры: `examples/input/` (два списка, включая файл с дубликатами, пропущенными оценками и ошибочными строками, и два записанных файла сохранения) и `examples/output_expected/` (эталоны разбора, рейтингов, экспортов и таблиц оценок).
- `scripts/smoke_test.py` переписан: сценарные сессии в обоих режимах (выбор, пропуск, отмена, autosave → загрузка → продолжение), сверка экспортов с эталонами, проверка правил из `docs/scoring_rules.md`, записанные и испорченные файлы сохранения. Пишет только во временный каталог.
- После экспорта окно показывает итог: «Готово. / Записано тайтлов: N / Ошибок: 0 / Результат: путь».

Изменено (заметно пользователю):

- JSON-экспорт рейтинга теперь объект `{"contract_version": 1, "kind": ..., "items": [...]}`, а JSON-экспорт истории матчей — `{"contract_version": 1, "kind": ..., "matches": [...]}`; раньше это были голые списки.
- Пример `examples/sample_input.txt` переехал в `examples/input/sample_input.txt`.
- `docs/scoring_rules.md` и `docs/input_format.md` дополнены тем, что код делал и раньше, но в документах не было: размер и приоритет «элитного ядра» в хардовом режиме, оценки на коротких списках, порядок построения рейтинга, разбор дубликатов и записей без оценки. Сами правила оценивания не менялись.

Исправлено:

- Отмена выбора портила турнир: после «Отменить последний выбор» и повторного выбора победитель пары попадал в следующий раунд дважды (мог встретиться сам с собой), а в турнире получалось на одну пару больше. Причина — снимок для отмены делил списки с живым состоянием. Теперь отмена возвращает состояние точно таким, каким оно было до выбора.
- Сохранения версии 0.1.0, в которых уже есть следы этой ошибки, при загрузке исправляются по истории матчей; если турнир успел уйти в следующий раунд с задвоенным участником, файл отклоняется с объяснением.
- Повреждённый или чужой файл autosave давал английский текст исключения, а чужой JSON-объект молча открывал пустой турнир. Теперь — понятная русская ошибка с путём к файлу, файл не трогается. Файл от более новой версии программы не загружается и не портится.
- Autosave пишется через временный файл с заменой: оборванная запись больше не оставляет обрезанный файл.
- Запуск без PySide6 печатает русское сообщение с командой установки вместо traceback; `run.sh` и `run.bat` сообщают об отсутствии Python.

## 0.1.0

Состояние до M3 (зрелость M2, статус `working`):

- GUI на PySide6: импорт TXT-списка, турнир на выбывание с попарным выбором, пропуск пары, отмена, autosave, окно результатов.
- Два режима оценивания (лайтовый и хардовый), правила в `docs/scoring_rules.md`.
- Экспорт рейтинга в TXT, CSV, JSON и истории матчей в JSON.
- Smoke-тест проверял парсер, турнирный движок, рейтинг и оба режима оценивания на одном примере.
